# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Android-приложение «Crnogorski» — персональный тренажёр черногорского языка (русский → черногорский, латиница) для одного пользователя. Kotlin + Jetpack Compose, Room, Claude Haiku для проверки свободных переводов. Без геймификации, без аккаунтов, без сервера: уроки лежат в `assets`, прогресс — в локальной Room-базе.

Документация проекта на русском; комментарии в коде тоже. Пиши в том же стиле.

- `README.md` (в `src/`) — сборка, форматы заданий, устройство проверки, речь.
- `STATUS.md` (в корне) — принятые решения, что ещё не проверено, ближайшие задачи. **Обновляй его по ходу работы** — это способ передачи контекста между сессиями.
- `research/` — разведка свободных источников для новых уроков: каталог с лицензиями (`research/README.md`), план уроков 9–20 (`research/plan-urokov.md`), скачанное сырьё (`research/data/`) и скрипты сбора (`research/tools/`). В сборку не входит.

## Структура и сборка

Корень Gradle-проекта — подпапка **`src/`**, а не корень репозитория. Все команды выполняются оттуда:

```
cd src
./gradlew assembleDebug          # сборка
./gradlew installDebug           # установка на подключённое устройство
./gradlew :app:compileDebugKotlin  # быстрая проверка компиляции
./gradlew pullComplaints         # забрать жалобы с телефона в app/build/complaints.jsonl
```

Перед первой сборкой нужен `src/local.properties` (шаблон — `src/local.properties.example`):

```
sdk.dir=/путь/к/Android/sdk
ANTHROPIC_API_KEY=sk-ant-...
```

Ключ подставляется в `BuildConfig.ANTHROPIC_API_KEY` из `app/build.gradle.kts` и в git не попадает.

Wrapper в репозитории есть — **Gradle 8.11.1**, зафиксирован сознательно: AGP 8.7.2 требует Gradle 8.9+ и с веткой Gradle 9.x не работает. Не обновляй wrapper, не подняв заодно AGP. Тестов в проекте нет.

`minSdk = 34` (Android 14) — ниже не спускаемся сознательно: старых устройств у владельца нет. `compileSdk`/`targetSdk` остаются 35.

### namespace ≠ applicationId — так и задумано

`namespace = "com.crnogorski.trener"` (пакет исходников, от него считаются `BuildConfig` и `.MainActivity` в манифесте), а `applicationId = "com.montelearn"` — идентификатор установки на устройстве. Расхождение намеренное: раньше `namespace` был `com.montelearn`, из-за чего не разрешался `com.crnogorski.trener.BuildConfig` и сборка падала. Если решишь свести всё к одному имени — переноси пакеты исходников, а `namespace` держи равным пакету.

## Архитектура

Один Activity, один ViewModel, два экрана, никакой навигационной библиотеки: `MainActivity` показывает `HomeScreen` или `SessionScreen` в зависимости от того, `null` ли `AppViewModel.session`.

```
assets/lessons/*.json ──> LessonRepository ──┐
                                             ├──> AppViewModel ──> HomeScreen / SessionScreen
Room (cards, lesson_progress) ──> AppDao ────┤
                          Scheduler (SM-2) ──┘
                          HaikuChecker (api.anthropic.com)
                          Speaker / Listener (TTS, распознавание речи)
```

`AppViewModel` — единственное место, где сходится вся логика: сборка сессии (урок или повторение), выбор способа проверки, запись карточек в SRS, завершение урока. `SessionState`/`Phase` (`Input` → `Checking` → `Result` | `Blocked`) описывают весь экран задания.

### Два способа проверки — ключевое разделение

`Exercise` — sealed class с девятью подтипами, дискриминатор в JSON — поле `type` (`classDiscriminator = "type"` в `LessonRepository`).

- **Локально, офлайн** (`LocalCheck` в `LessonRepository.kt`): `choice`, `word_bank`, `form`, `listening`, `speaking`, `repeat`, `reading`. Нормализация регистра, пунктуации и пробелов; **диакритика значима** (č/ć/š/ž/đ различают слова). Исключение — речь: `matchesSpoken` сплющивает диакритику, потому что движок распознавания её теряет.
- **Экавица засчитывается наравне с иекавицей.** `LocalCheck.reflex` сводит `lijepo` и `lepo` к одному виду сплошной заменой `ije` → `e`, затем `je` → `e`, плюс списком для несплошных случаев (`sjutra` → `sutra`, `đe` → `gde`). Курс черногорский, но правильный сербский ответ ошибкой не считается — решение владельца.
  Терпимость только там, где ответ **набирают**: `matchesTyped` для `form` и `listening`, `matchesSpoken` для речи, свёртка внутри `readingScore`. Там, где вариант **выбирают** из показанных, работает строгий `matches`: в l06e07 выбор между `sutra` и `sjutra` — и есть всё задание. Это единственное столкновение во всём курсе, проверено свёрткой всех 106 ответов и вариантов.
- **`reading` считается отдельно.** `LocalCheck.readingScore` берёт долю слов текста, прозвучавших по порядку (наибольшая общая подпоследовательность), порог — 75% (`ReadingScore.PASS`). Дословного совпадения на трёх предложениях не бывает: движок склеивает слова и теряет предлоги. Порядок при этом учитывается — иначе те же слова вразнобой считались бы чтением.
- **Через Claude Haiku** (`HaikuChecker`): `ru_to_me` и `me_to_ru` — свободные переводы, где допустимы синонимы и другой порядок слов. Расширение `Exercise.needsModelCheck` — единственный источник истины о том, какие типы требуют сети.

Если в сессии есть задания с `needsModelCheck`, а сети нет, `guardNetwork` сразу переводит экран в `Phase.Blocked` и не даёт начать урок. Это осознанное решение (см. STATUS.md), а не недоделка.

`HaikuChecker` дёргает Messages API напрямую через OkHttp (модель `claude-haiku-4-5-20251001`, `temperature = 0`), просит вернуть один JSON-объект `{correct, feedback, better}` и парсит его в `Verdict`. Если вердикты придирчивы или, наоборот, слишком мягкие, правится системный промпт в `HaikuChecker.kt`, а не логика приложения. Промпт правился по жалобам дважды и сейчас требует прямо: сперва проверить, нет ли прочтения, при котором ответ верен (другая идиоматичная конструкция ошибкой не считается); не путать диакритику с иекавицей; название падежа добавлять, только если оно точно верное. Ответ начат за модель открывающей скобкой (prefill), поэтому обёртки ```json она выдать уже не может, а `firstJsonObject` вырезает первый сбалансированный объект и не спотыкается о приписки после него. Если объекта нет вовсе, задание уходит в `Phase.Blocked`.

### SRS

`Scheduler` — упрощённый SM-2 с бинарной оценкой: верно → интервал 1 → 3 → `interval × ease` (дни), ease растёт до 3.0; неверно → сброс, ease −0.2 (не ниже 1.3), карточка возвращается через 10 минут, то есть ещё в текущей сессии. Карточка привязана к `exerciseId`, поэтому прогресс переживает добавление уроков.

Блок «Повторение» на главном экране собирает просроченные карточки из всех уроков, но **не больше `REVIEW_LIMIT` = 25 за подход**, самые старые первыми. Без потолка сессия однажды станет из сотен заданий, и её нельзя будет ни закончить, ни бросить без потери; счётчик на главном при этом честный, а про остаток сессия говорит в заметке.

`startReview` разбирает не весь курс, а только уроки просроченных карточек (`repo.exercisesIn` по `lessonId`): при полусотне уроков разница между двумя файлами и всеми пятьюдесятью заметна на глаз.

Кнопка «Пропустить» в задании на произношение — отдельная ветка `Phase.Skipped`, а не ответ: `Scheduler.postpone` двигает `dueAt` на несколько часов, не трогая `ease`, `repetitions` и `intervalDays`. Ошибкой не считается и в счёт урока не идёт. Раньше кнопка слала пустую строку, которую `submitText` отсекал на входе, — то есть не делала вообще ничего.

### Жалобы на задания

Кнопка «Пожаловаться на задание» на экране результата. Жалоба — заметка себе о том, что задание кривое, и попадает в JSONL: `ComplaintStore` дописывает строку в `complaints.jsonl` в каталоге приложения на внешней памяти (`/sdcard/Android/data/com.montelearn/files/`). Оттуда её забирает `./gradlew pullComplaints` — root и разрешения не нужны, сети тоже: жалоба нужна ровно тогда, когда задание сломано, в том числе офлайн.

Ключ записи — `exerciseId`: он уникален по курсу и не меняется между версиями, поэтому по нему сразу находится строка в файле урока.

Главное поле — **категория** (`ComplaintReason`), а не свободный текст: она говорит, что чинить. `verdict_wrong` — системный промпт в `HaikuChecker.kt`; `reference_wrong`, `ambiguous`, `typo` — JSON урока; `audio_unclear` — само задание. Коды категорий уходят в файл и не должны меняться, иначе старые жалобы не сгруппируются с новыми.

Жалоба заодно **откатывает карточку SRS** к состоянию до ответа (`AppViewModel.cardBeforeAnswer`): ответ на сломанное задание ничего не говорит о знаниях, а лапс возвращал бы карточку каждые 10 минут до самой починки урока.

Рядом с шестерёнкой в шапке (и в шапке урока тоже) — флажок: жалоба, **не привязанная к заданию**. Открывается диалогом поверх экрана, а не отдельным экраном: пожаловаться можно посреди задания («голос читает слишком быстро»), и урок при этом не должен ни сбиваться, ни перематываться — набранный ответ и распознавание под диалогом остаются на месте. Пишет `AppViewModel.addNote`: та же строка JSONL, причина — `NOTE_REASON` (`"note"`), категорий нет (чинить по такой записи нечего конкретного, весь смысл в тексте). SRS и `complaintFiled` не трогает.

Если жалоба написана посреди урока, `exerciseId` всё же заполняется — как место, где это случилось, а не как предмет жалобы; отличает их именно причина `note`. Подтверждение приходит `Snackbar`-ом из `MainActivity` и **после** записи в файл, а не по нажатию: внешняя память может быть недоступна.

Схема Room при этом не менялась — жалобы живут в файле, миграция не нужна.

Шестерёнка в шапке `HomeScreen` открывает `SettingsScreen` — третий экран, разведённый в `MainActivity` тем же ручным `if`, что и сессия (`navigation-compose` в зависимостях объявлен, но не используется). Там:

- **«Отправить отчёт»** — системная шторка (`ACTION_SEND` + `createChooser`). Файл отдаётся через `FileProvider` с authority `${applicationId}.files` (`res/xml/file_paths.xml`): прямой `file://` с Android 7 роняет получателя через `FileUriExposedException`. Целиться в конкретный мессенджер смысла нет — Telegram есть в шторке и так, а бот потребовал бы второй секрет в APK.
- **«Очистить»** — `ComplaintStore.archive()`, который **переименовывает** файл в `complaints-sent-<дата>.jsonl`, а не удаляет. `ACTION_SEND` не возвращает результат: приложение не знает, дошла ли отправка, поэтому удаление по факту нажатия однажды потеряло бы жалобы молча. Дубли безопаснее — `ts` и `exerciseId` схлопываются на стороне разработчика.
- **«Проверить синтез речи»** — произносит фразу и показывает `Speaker.voiceUnavailable`: голоса `sr-RS` может не быть, и это единственный способ проверить, не запуская урок.

### Подсказки по словам

`assets/glossary.json` — плоский словарь `{me: {...}, ru: {...}}`. Знакомое слово в задании подчёркнуто, по нажатию перевод появляется строкой ниже (не всплывающей подсказкой: на телефоне палец закрывает ровно то место, куда нажали). Слова, которого нет в словаре, подчёркивание не касается — сразу видно, на что нажимать бесполезно.

Ключ — **словоформа как она стоит в задании**, в нижнем регистре, а не начальная форма: разбирать морфологию на устройстве нечем, да и «plažu — пляж (вин. п.)» полезнее отсылки к словарной статье. Направление выбирается по языку показанного текста, а не задания: у `ru_to_me` подчёркивается русское условие и ведёт в черногорский, у `me_to_ru` наоборот. Условия `choice` не подчёркиваются — это инструкция, а не текст для перевода.

Добавляя урок, дополни и словарь: `LessonRepository.glossary()` читает файл один раз за запуск и при поломке молча отдаёт пустой — подсказки исчезнут, задания будут работать.

### Речь

Локали «черногорский» в Android нет — используется `sr-RS` с латиницей (`Speech.kt`). `Speaker` (TTS) озвучивает `listening`-задания; `Listener` (SpeechRecognizer) распознаёт `speaking` и `reading`. Качество произношения не оценивается: достаточно того, что движок распознал фразу. `Speaker` живёт в `MainActivity` и передаётся в `SessionScreen` параметром.

Черногорское озвучивается **само**, как только задание появилось (аудирование, перевод с черногорского, выбранный вариант); кнопки «Прослушать» и «Медленнее» остаются. `Speaker` запоминает фразу, пришедшую до готовности движка, — инициализация TTS асинхронная, иначе первое задание за запуск молчало бы.

`Listener` держит один распознаватель на экран и **не пересоздаёт** его на каждую попытку: свежий объект привязывается к системному сервису не мгновенно, отчего первое нажатие срывалось с ошибкой 11 (`ERROR_SERVER_DISCONNECTED`), а второе работало. Ошибки из набора `TRANSIENT` (11, 5, 8) он повторяет сам, молча, один раз через 300 мс — человек всё равно нажал бы кнопку заново.

`AnswerLanguage` разводит язык **ответа**, а не задания: у распознавания и у клавиатуры теги разные (`sr-RS` против `sr-Latn-RS`, иначе Gboard откроет сербскую кириллицу). Клавиатура при этом встаёт именно сербской латиницей — черногорской в Android нет вовсе (код `cnr` ни одна раскладка не поддерживает), а набор букв для курса тот же. Отсюда же `hintLocales` в полях ввода и микрофон (`MicButton`) — продиктовать ответ вместо набора. В `listening` микрофона нет намеренно: продиктовать услышанное значит поручить распознавателю ровно ту работу, ради которой задание и есть.

### Истории

Отдельный формат для чтения вслух: связный текст в 10–20 отрезков,
`assets/stories/index.json` плюс файл на историю. Отрезок нарезан **заранее,
в файле**, и у каждого свой перевод: делить фразу и переводить её половинки —
разные задачи, вторую машина не решает.

**Занятий на одном тексте три** (`StoryMode`), и на главном экране это три
складные группы с одним и тем же списком историй.

- **Чтение вслух** (`Read`) — показан черногорский, надо его произнести.
  Проверяется на месте, `LocalCheck.readingScore`, сеть не нужна.
- **На слух** (`Listen`) — текст закрыт прочерками, отрезок звучит сам, и
  повторить его надо с голоса. Проверка та же местная: важно, что расслышал,
  а не как перевёл.
- **Перевод вслух** (`Translate`) — показан русский, сказать надо
  по-черногорски. Проверяет `HaikuChecker.checkSpoken`: одну мысль выражают
  по-разному, и сравнение строк тут просто врёт.

Прогресс у занятий раздельный: первичный ключ `story_progress` составной,
`(storyId, mode)`. Общим он быть не может — прочитанная история открывалась бы
переведённой. Схема Room из-за этого поднялась до версии 3, миграция 2→3
пересоздаёт таблицу (ключ в SQLite на месте не расширяется) и переносит старые
строки как чтение.

Отрезок повторяют, пока не выйдет (порог тот же, что у `reading`, —
`ReadingScore.PASS`), и только после этого под ним появляется перевод: он тут
награда, а не подсказка. После нескольких неудач подряд отрезок можно оставить —
движок распознавания ошибается сам по себе, и упереться в него навсегда нельзя.

**При чтении нажимать нечего, пока всё получается.** Отрезок появился —
распознавание уже слушает; прочитал — перевод открылся, и следующий отрезок
слушает сам. Кнопка возвращается ровно тогда, когда что-то сорвалось: не
разобрали, нет доступа к микрофону или человек прервал прослушиванием образца
(слушать и говорить одновременно нельзя — запись подхватила бы голос
синтезатора).

**На слух отрезок сам звучит и сам переходит в запись.** Микрофон включается по
концу фразы, а не по таймеру: слушать и говорить одновременно нельзя. Отсюда
`Speaker.speak(text, slow, onDone)` — колбэк на `UtteranceProgressListener`,
вызываемый на главном потоке ровно один раз. Номер фразы сквозной, а не хэш
текста: два одинаковых отрезка подряд дали бы один идентификатор, и конец
первого засчитался бы за конец второго. Оборванную фразу (`onStop`) не
продолжаем — но только если номер совпал с текущим: `QUEUE_FLUSH` останавливает
старую уже после того, как назначена новая. Кнопки «Ещё раз» и «Медленнее» там
переигрывают фразу целиком и снова слушают: «не расслышал» значит «дай ещё раз
послушать», а не «нажми и говори».

Прочерки — по одному на букву или цифру, через пробел; знаки препинания
остаются как есть. Длина слов и их число не подсказка, а условие задачи: слышно,
сколько всего надо разобрать и не потерялось ли слово. Пустое место этого не
говорит.

**При переводе кнопка есть всегда, и само оно не слушает.** Перевод надо сперва
придумать, а самослушающий экран торопил бы: отсчёт тишины пошёл бы раньше
первого слова. По той же причине молчание там не переслушивается молча, как при
чтении, — кнопку нажали сознательно.

После трёх неудач подряд — и при переводе, и на слух — черногорский текст
**показывается** (`StoryState.revealed`), и отрезок с этого места работает как
чтение: задача уже не «переведи» и не «расслышь», а «произнеси», проверяется она
на месте и сети не требует. Отсюда единственная развилка в `StoryScreen`:
`hearing` и `translating` значат «текст ещё закрыт», всё остальное — обычное
чтение вслух, одним и тем же `ReadingControls`. При переводе тогда же появляются
«Послушать» и «Медленнее» — до подсказки образец и был бы ответом. Бросить
отрезок дают только через две неудачи **после** подсказки: разрешить это сразу
значило бы обессмыслить её.

Неудачу проверки (нет сети, сервер ответил ошибкой) за попытку **не** считаем:
иначе оборванная связь через три отрезка открыла бы ответ за человека. Сеть при
переводе проверяется на входе в историю, как `guardNetwork` у уроков.

Промпт для устного перевода отдельный (`spokenPrompt`), а не общий с письменным,
из-за диакритики: в письменном её пропуск — ошибка (č и c разные буквы), в устном
её нет вовсе, потому что движок распознавания её не выдаёт. Требовать её от
голоса значило бы не засчитать ни один верный ответ.

Три тонкости, на которых легко ошибиться, и на всех трёх успели ошибиться.

1. Неудачу экран узнаёт **по счётчику попыток**, а не из `onResult`: засчитано прочитанное или нет, решает `AppViewModel`.
2. `paused` и `stalled` намеренно **не** входят в ключи запускающего эффекта — их снимает нажатие, которое и так зовёт `start()`, иначе распознавание запустилось бы дважды подряд.
3. **«Ничего не расслышал» — не то же, что «прочитано неправильно».** Первое не увеличивает счётчик попыток, и без отдельной обработки (`Listener.onSilence`) экран оставался в самослушающем режиме с крутящимся индикатором и не делал ничего. Молчание переслушивается само дважды, дальше возвращается кнопка.

Перед автозапуском — полсекунды паузы: движку надо отпустить предыдущий заход, человеку — довести глаза до новой строки. Без неё распознавание сдавалось раньше, чем начиналось чтение.

Текст истории — `LazyColumn` с прокруткой к текущему отрезку, а не колонка со скроллом: прочитанное копится сверху и выталкивало читаемую строку за нижний край. В хвосте всегда есть элемент высотой в окно (`fillParentMaxHeight`, **не** `fillMaxHeight` — внутри списка высота не ограничена, и он схлопнулся бы в ноль), иначе последний отрезок не доводился бы до верха.

Истории **вне SRS**: карточек не заводят, на повторение не встают, прогресс
лежит в своей таблице `story_progress` и хранит только «докуда дошёл».
Пройденная история открывается с начала — «продолжить с конца» это пустой экран.

Форма `CREATE TABLE` в миграциях ровно та, что генерирует Room (сверять по
`app/build/generated/ksp/.../AppDb_Impl.java`): расхождение уронило бы приложение
на запуске.

### Копия прогресса

Прогресс переживает переустановку двумя способами, и они не заменяют друг друга.

**Auto Backup от Android** — даром и без кода: `allowBackup="true"` плюс
`<include domain="database" path="."/>` в `res/xml/data_extraction_rules.xml`.
Система сама выгружает `crnogorski.db` в Google Drive и возвращает при установке
начисто. Отстаёт на сутки, требует Google-аккаунт, молча не срабатывает.

**Своя копия** (`data/ProgressStore.kt`) — после каждой сессии пишется
`crnogorski-progress.json` с обеими таблицами, в два места:

1. **всегда** — в каталог приложения на внешней памяти, рядом с жалобами. Ничего
   не требует: ни выбора папки, ни разрешений, ни установленного облака. Удаление
   приложения её уносит, зато она есть при любом раскладе и видна файловым
   менеджером;
2. **если выбрана папка** (`ACTION_OPEN_DOCUMENT_TREE`, право берётся постоянным) —
   ещё и туда. Папка не наша, поэтому удаление приложения файл не трогает. Право
   на папку переустановку **не** переживает: после неё папку указывают заново,
   файл при этом на месте.

Неудача записи в папку не остаётся незамеченной: `SaveResult.folder` отличает
«папки нет» от «папка есть, а записать не вышло», и последняя попытка показана
в настройках строкой «Последняя копия». Молча не сохранять там, где человек
рассчитывает на сохранение, — худшее, что может делать резервное копирование.

Восстановление **ничего не удаляет**: карточки вливаются по `exerciseId`, при
совпадении побеждает файл. Терять данные восстановление не должно уметь.

Настройка папки лежит в `SharedPreferences` и в Auto Backup намеренно не входит:
восстановить путь, право на который всё равно утрачено, — только запутать.

### Главный экран: вкладки и разделы

Две вкладки — уроки и истории, — переключаются иконками слева в той же строке, что жалоба и шестерёнка справа. Заголовок под ними меняется вместе с вкладкой.

Складные разделы есть на обеих вкладках, и заголовок у них общий: у уроков это `section` из `index.json`, у историй — занятие (`StoryMode`, порядок объявления = порядок групп). Список историй во всех группах один и тот же, разное — что с текстом делают; ключ строки поэтому с режимом, иначе список нашёл бы одинаковые.

У `LessonRef` есть поле `section`. Уроки с одинаковым разделом, **идущие подряд** в `index.json`, собираются в группу с липким складным заголовком; порядок задаёт файл, раздел его не перетасовывает. Пустая строка значит «без заголовка» — такая группа всегда открыта, и старый `index.json` не ломается.

Разделы **свёрнуты по умолчанию**: их будет много, а нужен за раз один.

Выбранная вкладка и список открытых разделов лежат в `AppViewModel` **рядом** с `HomeState`, а не внутри него: состояние пересобирается целиком после каждого урока, и то, что человек открыл руками, схлопывалось бы у него на глазах при каждом возвращении.

## Добавление уроков

1. Новый файл в `src/app/src/main/assets/lessons/`, строка в `index.json` (с `section`), `versionCode` +1.
   Прогресс от этого не страдает: карточки привязаны к `exerciseId`, а он у новых заданий новый. Схема Room при добавлении уроков **не меняется**, миграция не нужна.
2. **`id` заданий уникальны по всему курсу и не меняются между версиями** — иначе теряется история повторений. Схема: `l09e01`.
3. Форматы всех девяти типов заданий — в `src/README.md`; канонические типы — в `data/Model.kt`.

При добавлении нового типа задания нужно тронуть пять мест: `Exercise` в `Model.kt`, `referenceAnswer`, `typeName`, `submitText` в `AppViewModel.kt` и рендер в `SessionScreen.kt`.

`speaking` и `repeat` рисует один `SpokenAnswer`, разница во флаге `byEar`: фраза звучит сама, а текст закрыт до кнопки «Показать текст» — опереться должно быть не на что, кроме услышанного. После ответа текст открывается сам, иначе не с чем сверить.

У `reading` свой блок `ReadingAnswer`, и читается текст **по предложению**. Целиком не выходит: движок распознавания на длинной фразе возвращает «ничего не расслышал», а просьбы не обрывать запись на паузе (`EXTRA_SPEECH_INPUT_*_SILENCE_LENGTH_MILLIS`) документация Android разрешает игнорировать — что он и делает. Пробовали, получили три жалобы подряд, убрали. Один заход распознавания — одно предложение; услышанное склеивается и оценивается целиком. Сорванное предложение перечитывается на месте, прочитанное раньше не теряется.

## Оформление

Серифные заголовки — `ui/Theme.kt`. Цвета берутся оттуда (`Ink`, `Paper`, `Accent`, `Crimson`, `Jade`…), не хардкодятся по месту.

Тем две, и выбирает между ними ночной режим системы (`isSystemInDarkTheme`); своего переключателя нет намеренно. Имена цветов — **роли**, а не значения: `ink` — фон, `paper` — текст по нему, поэтому в светлой теме светлота меняется местами, а экраны о теме не знают ничего. Технически это композабельные геттеры поверх `LocalPalette`, отсюда правило: **цвет читается только из `@Composable`-кода**. Фон окна до первой отрисовки Compose задаёт `res/values/themes.xml` и его пара `values-night` — без второй при светлой теме мигал бы чёрный экран.

Акцент называется `Accent`, а не `Gold`, потому что оттенок у него разный: в тёмной теме золото, в светлой синий. Тёмная тема тёплая — золото по чернилам; светлая холодная — синий по льду.

`Jade` — только для верного ответа: акцентом вердикт не отличался бы от кнопки.

Контрасты палитр считаны, а не подобраны на глаз: все пары «текст по фону» держат 4,5:1 и выше.
